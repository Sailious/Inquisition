# 前端接入注意事项：应用层 WAF

> 面向前端同学。后端新增了一层应用层 WAF（Web 应用防火墙），本文档说明它是否影响你，以及需要确认的几个问题。

## 一句话结论

**前端不需要改代码。** 这层防护完全在后端实现，对正常业务请求无感知。

---

## 一、后端做了什么

生产日志中发现自动化扫描器在批量探测敏感文件（单日 500+ 次），典型请求形如：

```
GET /media../.env
GET /static../.azure/accessTokens.json
GET /css../.env
```

这些请求此前由 Spring 内部拦截，但要走完整路由。现在后端在**请求进入业务逻辑之前**加了一层过滤器，命中扫描特征直接返回 `403`，不再占用业务资源。

### 拦截规则（只针对攻击特征）

- 路径穿越：`..`、`%2e%2e`、`..%2f` 等（含 URL 编码变体）
- 敏感文件：`.env`、`.git`、`.svn`、`.aws`、`.azure`、`accessTokens.json`、`id_rsa`、`wp-login` 等

### 不会误伤正常请求的设计约束

| 约束 | 说明 |
| --- | --- |
| 只检查 URI 的 path | query string 里的 `..` 不参与匹配，业务搜索参数不受影响 |
| 不读取请求体 | 不影响 base64 图片上传，无额外性能开销 |
| 放行 `OPTIONS` | 跨域预检直接放行 —— **对前端最关键**，见第二节 |
| 响应体不回显路径 | 只返回 `{"code":403,"msg":"请求被安全策略拦截","data":null}` |

---

## 二、前端可能感知到的唯一变化

**理论上没有。** 只有在请求真被判定为扫描时才返回 403。

如果出现 403，响应格式与其它接口一致：

```json
{ "code": 403, "msg": "请求被安全策略拦截", "data": null }
```

注意区分三种 403，**含义完全不同**：

| 响应 | 含义 | 来源 |
| --- | --- | --- |
| `403` + msg=`请求被安全策略拦截` | 被 WAF 拦截 | 本次新增 |
| `403` + 其它 msg | JWT 鉴权失败（权限不足） | 原有逻辑 |
| `401` | 未登录 / token 失效 | 原有逻辑 |

建议：若前端有统一响应拦截器，可针对 `msg=请求被安全策略拦截` 单独提示，避免和"权限不足"混淆。

### 关于跨域（重要）

前端在 `https://ark.sailwertech.top`，后端是另一个域名，属于跨域。

**后端已保证：`OPTIONS` 预检一律放行，不会被 WAF 拦截。**

原因是：跨域 POST（带 `Content-Type: application/json`）浏览器会先发 `OPTIONS` 预检，若它被拦截，前端所有写操作会集体失败，且表现为"网络错误"而非 403，极难排查。

另外，被拦截时若请求的 `Origin` 在后端 CORS 白名单内，响应会带上 CORS 头，确保前端能读到 403 状态码而不是网络错误。

## 三、需要前端确认的问题

1. **请求的 `Content-Type` 是什么？** 是 `application/json`，还是部分接口用了 `application/x-www-form-urlencoded`？（前者触发 `OPTIONS` 预检，后者不触发；后端两种都已放行，仅用于核对）

2. **有没有接口会把用户输入的原始字符串放进 URL 路径（path）？** 例如 `/user/search/<关键词>` 这种写法。若关键词恰好含 `..` 或 `.env` 会被误拦截。走 query string 或请求体则完全不受影响。

3. **图片/截图是否有"复制链接在新标签页直接打开"的场景？** 例如运维右键复制日志截图链接发给他人。（影响后端七牛防盗链是否开启"允许空 Referer"）

4. **是否有把图片 URL 分享到站外（微信、邮件）的需求？** 同上，影响七牛 Referer 防盗链的宽严配置。

5. **前端是否有统一的 HTTP 响应拦截器？** 若有，建议加一条 `code=403` 且 `msg=请求被安全策略拦截` 的分支（可选，非必须）。

---

## 四、如果遇到疑似被误杀的请求

请提供以下信息给后端：

1. 完整请求 URL（path 即可，query 可脱敏）
2. 请求方法（GET / POST / OPTIONS）
3. 请求头中的 `Content-Type`
4. 浏览器控制台看到的响应状态码与响应体

后端可据此快速判断是规则误杀还是真实攻击特征，并临时关闭开关（`inquisition.security.waf.enabled=false`）排查。
